# Domain Form Inventory and Ownership Map

## Summary

This is a current-state inventory of Brunch Body form-like and input surfaces by domain. It records what the live code exposes today, which surfaces are reachable UX, which are reusable primitives or search/filter inputs, and which are dormant residue, test-only, or docs-only references.

This artifact is docs-only. It does not change form behavior, validation, persistence, copy, accessibility, routes, storage, tests, export behavior, privacy/disclosure language, measurement behavior, or Phase 1 local-first/profile-only terminology.

## Scope Boundary

In scope:

- Inventory current form/input surfaces in reachable Brunch Body domains.
- Classify form-like surfaces by current role.
- Record fields, value types where visible, validation, submit/save, dismissal, ownership, test coverage, risks, and follow-on lane seeds.
- Preserve active-code reachability and persistence boundaries.

Out of scope:

- Runtime source changes, test changes, shared-component refactors, route changes, schema changes, storage-key changes, copy changes, accessibility remediation, measurement conversion changes, export/import changes, privacy/disclosure changes, backend/cloud/sync work, reminders/notifications, AI work, or medical/nutrition-advice work.

## Source-of-Truth Rule

Live source is the source of truth. Existing architecture docs were used only for context and terminology boundaries. When docs and code differ, this inventory follows current code.

Phase 1 terminology is preserved:

- Reachable user-facing identity is device-local `Profile`.
- Profile data is local-first and profile-only.
- Settings account/auth/password route names and files that are not mounted in live navigation are classified as dormant/internal residue, not reachable UX.
- The reachable destructive settings flow is documented by its current local-data behavior, with internal file/action names recorded only as evidence.

Unknown ownership is written as `unknown/not verified` rather than inferred.

## Classification Legend

| Classification | Meaning |
| --- | --- |
| `reachable_domain_form` | Mounted or reachable domain UX that accepts user-entered domain data and saves/submits it. |
| `reachable_profile_or_onboarding_form` | Mounted profile/onboarding UX that writes device-local profile data or onboarding draft data. |
| `reachable_settings_form` | Mounted settings UX that edits profile/settings-owned local data or confirms a settings-owned action. |
| `reachable_modal_form` | Mounted or caller-reachable modal form surface that accepts data before submit/save. |
| `reusable_input_component` | Shared or domain-local input primitive/picker/modal content with caller-owned state and persistence. |
| `search_or_filter_input` | Input used to search, filter, select, or navigate, not to submit domain data directly. |
| `dormant_route_or_source_residue` | Source, route constants, helper branches, or screens present in the repo but not proven reachable in live navigation. |
| `test_only_reference` | Test-only mock, assertion, or reference. |
| `docs_only_or_future_work_reference` | Existing documentation reference, future lane note, or historical context. |
| `unclear_requires_followup` | Surface found in code but reachability or ownership could not be proven in this lane. |

## Risks and Ambiguities

- Several domains use shared modal/input primitives, but validation and persistence remain caller-owned. Treating `TextInput`, `CreateItemContent`, or picker components as a central form system would be inaccurate.
- Profile data has both direct `user_profile` storage and a persisted `auth` slice. Current code makes direct `user_profile` the key bootstrap/profile owner, while redux-persist also stores the slice.
- Nutrition, calendar, todo, recreation, and exercise have storage helpers that read legacy/direct keys, while current screen mutations generally dispatch Redux actions and persist through the redux-persist root.
- Writing form source lives under `src/screens/writing` but is mounted through Calendar navigation wrappers.
- Calendar todo UX is calendar-owned, but action/storage ownership remains in the legacy `todo` slice/key.
- Recreation surfaces include both recreation slice data and exercise slice data; MyExercises is reachable through Recreation but persists through `exercise`.
- Dormant settings account/auth source files and route constants remain in the repo. They must not be treated as reachable Phase 1 UX without a future navigation/reachability change.
- Search/filter inputs appear beside real forms and sometimes feed selected values into forms, but the search inputs themselves do not submit domain data.
- This lane did not prove every list selector or export selector contract; those are classified narrowly and left for domain-specific lanes where needed.
