# Store Metadata and Creative System - 2026-06-13

## Metadata Source of Truth

Store metadata should describe Brunch Body as a local-first personal organization and tracking app for fitness, meals, journals, calendar items, routines, and profile-based in-app calculations. Public copy must match the current app, public docs, and release signoff records.

## Claim Review

Before metadata is submitted, review every headline, subtitle, screenshot caption, and feature bullet against current behavior:

- Local-first storage is the current posture.
- Export is user-managed and not a full app backup.
- Delete local data clears app-managed local data on the device and does not delete external copies.
- Help content is for app understanding, not professional guidance.
- AI assistance is not enabled in the current build.
- RC2 signed Android/iOS artifacts and owner approvals remain required for public submission.

## Creative Checklist

- Show real reachable app areas rather than aspirational features.
- Avoid screenshots that expose tester private data.
- Include Settings or Help language when showing export/delete/privacy controls.
- Keep accessibility-readable text sizes and contrast.
- Keep platform badges, version claims, and release claims pending until owner signoff.

## Forbidden Claims

- Automatic Brunch Body backup or restore.
- Backend account recovery or support-side inspection of local data.
- Remote deletion of files outside app-managed local storage.
- Professional medical, treatment, diagnosis, or emergency guidance.
- Enabled AI coaching or automated provider processing.
- Public release approval before the owner gate is recorded.

## Non-Claims

This artifact is a preparation system only. It does not submit store metadata, approve screenshots, approve launch, or change app runtime behavior.
